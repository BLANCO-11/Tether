perturb.P5_drop_grep_dash_a=DID NOT FIRE — and `grep -a` is therefore documented
#   as DEFENSIVE AND UNREACHABLE rather than required. Measured why: bash's `read`

#   file as "Binary files ... differ" with no `+` lines at all. A lone \001 does
#   NOT trigger grep's binary heuristic (verified both ways). The flag is kept for
#   a future caller that streams raw bytes; the comment in check-secrets.sh says
#   so explicitly, because a comment claiming necessity that no test can prove is
#   exactly the kind of false assurance this repository keeps warning about.

# ─────────────────────────────────────────────────────────────────────────────
# BUGS FOUND BY THE TESTS, not by reading. All three silently skipped content.
# ─────────────────────────────────────────────────────────────────────────────
bug1.trailing_tab=git appends a TAB to `+++ b/<path>` when the path contains a
#   space. The old parser kept it, so `odd dir/.env.local.example` arrived as
#   `...example<TAB>`, stopped matching `*.example`, was classified FORBIDDEN, and
#   forbidden files are content-exempt — so a planted key in it was NEVER SCANNED.
#   Pre-existing. Fixed here.
bug2.quoted_paths=git QUOTES paths containing non-ASCII bytes
#   (`+++ "b/pa\303\251th"`), which does not match `+++ b/*`, so every line of
#   such a file was skipped. Pre-existing. Fixed with `-c core.quotePath=false`.
bug3.pipe_swallows_exit_code=introduced DURING this change and caught by the
#   planted-secret tests: `{ ... } | scan_candidates` runs the matcher in a
#   subshell, so `report`'s FOUND=1 never reaches `exit "$FOUND"`. The scan found
#   the secret, printed SECRET-BLOCK, and exited 0 — the exact "fast scan that
#   reports success" failure the plan named as the risky half.
