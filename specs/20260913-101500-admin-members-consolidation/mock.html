The four access states stay: super admin · signed in but not one · none configured · could not be checked. The last one must never read as either answer.
The one behaviour change
“People who have signed in” assigned as admin in one click. Its replacement — the person picker in Assign across workspaces — asks for person, role and workspaces. That is one step more, and a better default: the old panel hardcoded admin, so everybody added through it became a workspace administrator whether or not anybody meant it. If the one-click path is wanted back it should be “Add to this workspace as…”, with a role picker — not a button that picks silently.
